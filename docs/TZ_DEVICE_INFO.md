# ТЗ: ассистент как источник информации о телефоне («полноценный помощник»)

Ветка: `device-info` (основана на `hotword-universal`). Пользователь: Максим, не программист, пишет по-русски. Ему нужна не столько работа руками ассистента, сколько **информация**: заряд, сеть, память, какие приложения что занимают, статистика. Консоль (Shizuku) подготовить, но пока не подключать.

## Правила
- Один коммит на задачу, понятные сообщения. Перед коммитом тесты проходят (`gradle testDebugUnitTest`, в CI это делается автоматически). CI должен быть зелёным.
- Не ломать то, что работает: слово активации («Пятница» по умолчанию, настраивается), слушание, музыка, заметки, напоминания, подтверждения.
- Универсальность: никаких личных данных в коде. Тексты для пользователя по-русски, простым языком.
- Приватность: всё, что читает чужие данные (экран, уведомления), **выключено по умолчанию**, включается пользователем отдельным переключателем и работает **только по просьбе**. Пароли не читать. Текст экрана обрезать (экономия токенов Groq, лимит ~8000 токенов в минуту).
- Только чтение. Любое действие, меняющее телефон (закрыть приложение, очистить кэш), только через подтверждение (`Confirm`).
- Если CI падает: ошибки смотреть в annotations запуска (`gh api repos/<owner>/<repo>/check-runs/<id>/annotations`), логи CI недоступны.

## Что уже сделано в ветке (проверено только компиляцией и юнит-тестами, на телефоне не запускалось)
1. `DeviceReport.kt` — чистый Kotlin: модели данных и тексты ответов (заряд, сеть, оперативная память, место, приложения по размеру и по времени). Тесты: `DeviceReportTest`.
2. `DeviceStatus.kt` — сбор данных: батарея (процент, зарядка, источник, температура, здоровье, время до полного, ток, экономия заряда), сеть (тип, работает ли интернет, платная ли, скорость, сила Wi-Fi, режим полёта), RAM, место, время в приложениях за 24 ч, размер каждого приложения (программа + данные + кэш). Приложения требуют «Доступ к истории использования» (`PACKAGE_USAGE_STATS`).
3. `DeviceActions.kt` — функция `report(context, section)` и объект `Privacy` (переключатель «Чтение экрана»).
4. Инструменты для модели в `Tools.kt`: `device_info` (section: battery, network, memory, storage, memory_all, apps_storage, apps_usage, processes, all) и `read_screen`; группа `device`.
5. Быстрые голосовые команды без модели в `LocalCommands.parseDeviceInfo` («сколько заряда», «какая сеть», «что занимает память», «какие приложения занимают место», «какое состояние телефона»…).
6. Чтение экрана: `AssistantAccessibilityService.readScreen()` (пропускает пароли, до 3000 символов).
7. Меню «Что ассистент может видеть» (боковое меню): чтение экрана, доступ к истории использования, служба спецвозможностей, пункт Shizuku («скоро»).
8. **Заготовка под Shizuku**: `ShellBackend.kt` — интерфейс `ShellBackend`, заглушка `NoShell`, объект `Shell` (`Shell.backend = ...`), парсер `ProcessReport.parseMeminfo` для `dumpsys meminfo` (с тестом). Раздел `processes` уже вызывает `Shell` и без консоли честно отвечает, что нужен Shizuku.

## Что осталось (по приоритету)

### Задача 1. Проверка и доводка на устройстве
- Собрать, убедиться, что CI зелёный. Проверить на Android 11+ (у пользователя Redmi): фразы «сколько заряда», «какая сеть», «что занимает память», «какие приложения чаще использую»; при первом вопросе про приложения должны открыться настройки «История использования».
- Критерий: каждая фраза отвечает за 1–2 секунды без обращения к модели, текст понятный, единицы указаны.

### Задача 2. Регулярные сводки и предупреждения («пусть давал статистику»)
- Ежедневная сводка уведомлением в выбранное время: заряд, свободное место, топ-5 приложений по времени и по размеру. Голосом: «присылай сводку по телефону каждый вечер в 21:00», «отключи сводку по телефону». Взять за образец `DigestActions` (сводки по интернету) и расписание на `AlarmManager`.
- Предупреждения (включаются в меню, по умолчанию выключены): заряд ниже 15% и не заряжается; свободного места меньше 10%; температура батареи выше 42 °C; пропал интернет надолго. Не чаще одного раза в несколько часов на каждый тип.
- Критерий: сводка приходит после перезагрузки телефона (перепланировать в `BootReceiver`), предупреждения не спамят.

### Задача 3. История замеров и тренды
- Раз в 30–60 минут (WorkManager или `AlarmManager`) сохранять замер: процент заряда, свободное место, свободная RAM (маленькая таблица Room или JSON, хранить 14 дней).
- Функция `device_history` (или раздел `device_info`): «как менялся заряд за день», «сколько теряю заряда в час», «когда место пропало».
- Критерий: ответ строится по сохранённым данным, без модели; при нехватке данных честно говорит об этом.

### Задача 4. Трафик и батарея по приложениям
- Трафик: `NetworkStatsManager` (нужен доступ к истории использования): «кто съел интернет за день/неделю», отдельно Wi-Fi и мобильный.
- Батарея по приложениям: без Shizuku — только время на экране из `UsageStats`; с Shizuku — `dumpsys batterystats` (см. задачу 5).
- Критерий: список в формате «1. Приложение — 1,2 ГБ», единицы и период указаны.

### Задача 5. Shizuku (подключить, когда пользователь скажет)
- Зависимости: `dev.rikka.shizuku:api` и `dev.rikka.shizuku:provider`, `ShizukuProvider` в манифест.
- Класс `ShizukuShell : ShellBackend`: проверка `Shizuku.pingBinder()`, запрос разрешения `Shizuku.requestPermission`, выполнение команд через `Shizuku.newProcess` или UserService. Включение: `Shell.backend = ShizukuShell` при старте приложения, если Shizuku запущен и разрешение выдано.
- Только белый список **читающих** команд: `dumpsys meminfo`, `dumpsys battery`, `dumpsys batterystats`, `dumpsys cpuinfo`, `top -b -n 1`, `ps -A`. Любая запись/остановка приложений: только через `Confirm`.
- Пункт «Shizuku» в меню «Что ассистент может видеть»: статус (не установлен / не запущен / нет разрешения / работает) и подсказка по настройке (Отладка по Wi-Fi → запустить Shizuku).
- Новые ответы: «что грузит телефон» (процессы по RAM и CPU), «какое приложение больше всего садит батарею», «температура и частота процессора».
- Критерий: без Shizuku всё остальное работает как раньше; раздел `processes` показывает топ процессов по памяти с названиями приложений.

### Задача 6. Уведомления и экран (по желанию пользователя)
- Чтение уведомлений: `NotificationListenerService`, отдельный переключатель (выключен по умолчанию), функция «что мне писали» (кратко, без паролей и кодов из СМС).
- Чтение экрана для приложений, которые не отдают текст: резервный путь через скриншот и существующую функцию `vision` (по просьбе).
- Критерий: ничего не читается без явного включения и без просьбы.

### Задача 7. Документация и версия
- README: раздел «Состояние телефона и приватность» (что умеет, какие разрешения, как включить, фразы-примеры).
- Версия и сборка не трогать вручную, если версия берётся из номера CI.

## Как проверять
`gradle testDebugUnitTest` (в CI). Новые тесты писать для чистого Kotlin (`DeviceReport`, парсеры, `LocalCommands`). Код, который зависит от Android, держать тонким.
